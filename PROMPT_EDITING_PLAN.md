# Plan: User-Editable System Prompts (Runtime WYSIWYG)

**Status:** Ready for implementation
**Goal:** Let users read and edit every AI system prompt from inside the app — no JS editing, no rebuild — with changes persisted across sessions and resettable to defaults.

This supersedes the earlier "external `public/prompts/*.md` files fetched at startup" proposal. See [§0 Why this design](#0-why-this-design-not-flat-files) for the reasoning. The original plan's *intent* (prompts out of code, user-editable) is fully preserved; only the *mechanism* changes.

---

## 0. Why this design (not flat files)

The earlier plan assumed each prompt is a single string with placeholders that can live in a `.md` file. The codebase is not shaped that way. From the audit of `src/modules/turns.js`:

- `askActor()` (lines ~1419–1779) branches into **four** distinct system-prompt builders — Director, Manager, Researcher, Participant — each an `Array(...).filter(Boolean).join("\n")` of **20–25 conditional lines**.
- Whether a given line is even present depends on runtime state: `sysCfg.dmNarrates`, `actor.canResearch`, `forceSpeak`, `showThoughts` tier, `stageDirectionsEnabled`, interaction mode, etc.
- Critical JSON-schema instructions are generated by `buildSchemaPromptLine()` / `buildActorSchema()` (from `schemas.js`) and **must not** be hand-editable or JSON parsing breaks.

A flat `director.md` with 16 `{{placeholders}}` would therefore be an unreadable skeleton, and the conditional logic still couldn't move out of JS. So:

> **Design principle:** The *prose* of each instruction block moves into an editable registry. The *decision of which blocks to include* stays in `turns.js`. Schema/transport lines stay 100% code-owned.

Benefits over the fetch-based approach:
- **No new failure mode** — defaults are a normal JS import, not a network/`fetch` that can 404 in production.
- **No `App.jsx` startup change** — overrides already live in persisted state; nothing to await.
- **Full HMR in dev** — editing default prose is a JS module edit, not a `public/` file that needs a hard reload.
- **WYSIWYG at runtime** — power users edit in-app; changes hit `localStorage` immediately via the existing `mutateState` path.
- **File-editing still possible** — Export/Import of the override set as JSON covers users who want to edit "a file" (§6).

## 1. Architecture overview

Three new pieces + edits to existing files:

| Piece | File | Role |
|---|---|---|
| Fragment registry | `src/prompts/registry.js` *(new)* | The default prose for every editable instruction block, keyed by stable id. Plain JS export — imported, never fetched. |
| Resolver | `src/prompts/index.js` *(new)* | `frag(id, vars)` → returns user override if present else default, substitutes `{{vars}}`. |
| Editor UI | `src/components/inspector/PromptsPanel.jsx` *(new)* | Inspector tab listing fragments grouped by prompt, with textareas, reset, badges, search, export/import. |
| State | `src/modules/constants.js` | Add `settings.promptOverrides` and `settings.promptOverridesMeta`. |
| Wiring | `src/components/inspector/Inspector.jsx` | Register the `prompts` panel. |
| Integration | `src/modules/turns.js`, `src/modules/session.js` | Replace inline prose literals with `frag(id, vars)` calls. |
| Tests | `src/prompts/registry.test.js` *(new)* | Resolver precedence, substitution, leftover stripping, coverage. |

Data flow (mirrors how `globalStylePrompt` already works — see `ConnectionPanel.jsx:139`, `state.js:374`):

```
PromptsPanel textarea
  → updateOverride(id, text)
  → mutateState(s => s.settings.promptOverrides[id] = text)   // localStorage debounce 300ms
turns.js / session.js
  → frag(id, vars)
  → reads state.settings.promptOverrides[id] || registry[id].default
  → substitutes {{vars}} → string
```

> **Granularity rule for the implementer:** one fragment per *named conditional block* found in `turns.js`. Use the block names already in the audit (`modeInstruction`, `dmRoleModifier`/role modifier, `castManagementBlock`, `concisenessRule`, `skipRule`, `flowControl`, `anchorSuggestions`, CAP-1/CAP-2, `styleControl`, `securityDirective`, etc.). Do **not** create a fragment per line, and do **not** collapse a whole 25-line prompt into one fragment — that would re-bury the conditionals. The registry above is a representative starter set; complete it by walking each builder path listed in §4.

### 2.2 What stays OUT of the registry (code-owned, non-editable)

These are generated by `schemas.js` and must never be user-editable:

- `buildSchemaPromptLine(...)` output (the JSON field instruction).
- `buildActorSchema(...)` output (the structured schema itself).
- The "JSON is transport only…" transport note.
- The `judge` / `intent` / `setup` **return-shape** lines (the `Return JSON only: {…}` strings). The *reasoning* prose is editable; the *shape* is appended by code after `frag(...)`.

The assembly code appends these unconditionally so a user edit can never break parsing. This satisfies the original plan's "JSON Format Protection" requirement.

## 3. The resolver — `src/prompts/index.js`

```js
// src/prompts/index.js
import { state } from '../modules/state.js';
import { REGISTRY } from './registry.js';

const PLACEHOLDER_RE = /\{\{\s*([\w.]+)\s*\}\}/g;

/**
 * Resolve an editable prompt fragment.
 * Precedence: user override (settings.promptOverrides[id]) → registry default.
 * Substitutes {{key}} from `vars`. Unknown/leftover placeholders are stripped
 * (replaced with '') and a dev warning is emitted, so raw {{x}} never reaches
 * the model.
 *
 * @param {string} id   Registry key, e.g. 'director.header'.
 * @param {Record<string, string|number>} [vars]
 * @returns {string}
 */
export function frag(id, vars = {}) {
  const entry = REGISTRY[id];
  if (!entry) {
    if (import.meta.env?.DEV) console.warn(`[prompts] unknown fragment id: ${id}`);
    return '';
  }
  const override = state.settings?.promptOverrides?.[id];
  const tpl = (typeof override === 'string' && override.length) ? override : entry.default;

  return tpl.replace(PLACEHOLDER_RE, (_, key) => {
    if (key in vars && vars[key] != null) return String(vars[key]);
    if (import.meta.env?.DEV) console.warn(`[prompts] ${id}: no value for {{${key}}}`);
    return '';
  }).trim();
}

/** True if the user has customised this fragment. */
export function isOverridden(id) {
  const v = state.settings?.promptOverrides?.[id];
  return typeof v === 'string' && v.length > 0;
}

/** Default text for a fragment (for the editor's "reset" + diff). */
export function defaultText(id) {
  return REGISTRY[id]?.default ?? '';
}
```

**Usage is a drop-in for the inline literals.** Example, Director header (currently `turns.js:1465`):

```js
// before
`You are ${actor.name}, the DM/director for a local AI forum.`,
// after
frag('director.header', { name: actor.name }),
```

The surrounding `[ ... ].filter(Boolean).join("\n")` and all conditionals are untouched.

### 5.3 `PromptsPanel.jsx` — the editor (new)

Mirror `ConnectionPanel.jsx` conventions exactly (`useForumState` selector + `mutateState` writer + `<Field>`/`<textarea>`).

```jsx
// src/components/inspector/PromptsPanel.jsx
import React, { useState } from 'react';
import { mutateState } from '../../hooks/useForumState';
import { useForumState } from '../../hooks/useForumState';
import { REGISTRY, GROUPS, REGISTRY_VERSION } from '../../prompts/registry.js';

export function PromptsPanel() {
  const overrides = useForumState(s => s.settings?.promptOverrides || {});
  const [filter, setFilter] = useState('');

  const setOverride = (id, text) => mutateState(s => {
    s.settings.promptOverrides ||= {};
    s.settings.promptOverridesMeta ||= {};
    if (!text || text === REGISTRY[id].default) {
      delete s.settings.promptOverrides[id];        // store nothing when == default
      delete s.settings.promptOverridesMeta[id];
    } else {
      s.settings.promptOverrides[id] = text;
      s.settings.promptOverridesMeta[id] = { defaultSnapshot: REGISTRY[id].default, v: REGISTRY_VERSION };
    }
  });

  const ids = Object.keys(REGISTRY).filter(id => {
    if (!filter) return true;
    const f = filter.toLowerCase();
    const e = REGISTRY[id];
    return id.includes(f) || e.label.toLowerCase().includes(f) || e.default.toLowerCase().includes(f);
  });

  // group ids by e.group, render a <section> per group, each fragment as a row:
  //  - label + id (mono) + "modified" badge when id in overrides
  //  - description line
  //  - placeholder chips: REGISTRY[id].placeholders.map(p => `{{${p}}}`)
  //  - <textarea value={overrides[id] ?? REGISTRY[id].default} onChange=...>
  //  - "Reset to default" button (visible only when id in overrides)
  //  - drift warning when overrides[id] exists AND
  //      promptOverridesMeta[id]?.defaultSnapshot !== REGISTRY[id].default
  // Top of panel: search box (filter), "Restore all defaults", Export, Import.
  return (/* … */);
}
```

UI requirements:
- **Grouped** by `GROUPS` (Director, Manager, …), collapsible sections.
- **Search box** filters by id / label / body.
- **Per-fragment:** label, mono `id`, description, **placeholder chips** (so the user knows which `{{vars}}` are valid), textarea, "Reset to default" (only when overridden), a **"modified"** badge.
- **Drift warning** per fragment: if an override exists and `promptOverridesMeta[id].defaultSnapshot !== REGISTRY[id].default`, show "⚠ Built-in default changed since you customised this — review." with a "view new default" toggle.
- **Restore all defaults** button → clears `promptOverrides`/`promptOverridesMeta`.

Add minimal styles to `src/styles/index.css` reusing existing `.field-hint`, badge, and `.btn sm` classes (see `pause-*` and panel styles already present).

## 6. Export / Import (covers "edit as a file")

Two buttons in `PromptsPanel`:

- **Export overrides** → download `forum-prompts.json` = `{ version: REGISTRY_VERSION, overrides: state.settings.promptOverrides }`.
- **Import overrides** → file picker → parse → validate each key exists in `REGISTRY` (drop unknown ids with a toast) → `mutateState` write.

This gives the file-editing workflow the original plan wanted, without a runtime `fetch`, and round-trips cleanly between machines.

## 7. Verification plan

### Automated (`src/prompts/registry.test.js`)
1. **Default precedence:** `frag('director.header', { name: 'Dir' })` → `"You are Dir, the DM/director for a local AI forum."`.
2. **Override precedence:** set `state.settings.promptOverrides['director.header'] = 'Hi {{name}}'` → `frag(...)` returns `"Hi Dir"`.
3. **Leftover stripping:** template with `{{missing}}` and no var → placeholder removed, no `{{` in output.
4. **Empty override falls back:** `promptOverrides['x'] = ''` → default used.
5. **Unknown id:** `frag('nope')` → `''`, dev warns.
6. **Coverage guard:** assert every id referenced by `turns.js`/`session.js` exists in `REGISTRY`. (Maintain a `USED_FRAGMENT_IDS` array exported from a small `src/prompts/used.js`, or grep in the test — simplest is a hardcoded list the test cross-checks so a removed registry key fails CI.)
7. **No placeholder leak in defaults:** for every registry entry, the set of `{{vars}}` in `default` ⊆ `entry.placeholders`. Fails the build if a default uses an undeclared placeholder.

Run: `npm run test`.

### Manual
- `npm run build` — succeeds; **no** `public/prompts` copy step needed (nothing fetched).
- Open app → **Prompts** tab renders all groups; editing `director.conciseness`, running a turn, and confirming the change appears in the Director's prompt (use the existing trace/`_lastPromptParts` debug view).
- Reset-to-default restores original; reload page → override persists (localStorage); "Restore all defaults" clears it.
- Edit a fragment, then change that fragment's `default` in code → reload → drift warning shows.

> **Parity caution for step 3:** when populating `REGISTRY[id].default`, copy the *exact* current wording from `turns.js` (the §4 line ranges), not the paraphrased samples in §2 — those are illustrative. The goal is zero behavioural change until a user actively edits a fragment.

## 9. Out of scope / follow-ups

- Per-actor prompt overrides (registry is global across actors of a kind).
- Live token-count preview in the editor.
- Versioned prompt "presets" beyond the single default set.
- Editing the JSON schema itself (intentionally locked).
